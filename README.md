# 會員照片標準化工作站 V14.5.1.1（GitHub Pages / MediaPipe）

## 部署方式

1. 將此資料夾內的所有檔案放到 GitHub repository 根目錄：
   - `index.html`
   - `style.css`
   - `app.js`
   - `.nojekyll`
2. GitHub repository → **Settings → Pages**
3. Build and deployment 選 **Deploy from a branch**
4. Branch 選 `main`、Folder 選 `/ (root)`
5. 儲存後等待 GitHub Pages 發布。

如果 repository 名稱是 `member-photo-editor`，網址通常會是：

`https://你的帳號.github.io/member-photo-editor/`

## V12 的人臉處理

V12 使用 MediaPipe Face Landmarker：

- JavaScript / WASM：從 jsDelivr CDN 載入
- Face Landmarker 模型：從 Google MediaPipe 模型儲存空間載入
- 所有會員照片仍在使用者瀏覽器內處理，程式沒有照片上傳 API

MediaPipe 用於：
- 2 吋大頭照自動裁切
- 批次自動裁切
- 臉部輪廓 / 五官定位
- 智慧臉部去污的安全皮膚遮罩

如果 MediaPipe 因網路或 CDN 無法載入：
- 自動找臉 / 自動 2 吋裁切 / 臉部智慧去污會無法使用
- 旋轉、手動裁切、亮度、對比、飽和度、銳化、去污筆、下載等功能仍可正常使用

## 2 吋裁切方向

- 比例：3.5 × 4.5 公分
- 頭頂至下顎：目標約佔照片高度 75%
- 合理方向：70%～80%
- 自動裁切只產生建議框；單張模式仍可微調後再套用
- 批次模式會直接套用，未辨識到可靠臉部的照片會跳過

## 注意

`file://` 直接雙擊開啟時，瀏覽器對 ES Module / CDN 的安全限制可能不同。
正式使用建議放在 GitHub Pages、localhost 或其他 HTTPS 靜態網站環境。


## V12.1 修正

V12 原版使用靜態 default import 載入 MediaPipe CDN。在某些瀏覽器 / jsDelivr
套件入口組合下，JavaScript 可能在 app.js 模組解析階段直接中止，畫面因此永久顯示
「MediaPipe 載入中…」。

V12.1 改為：
- dynamic import
- 固定 `@mediapipe/tasks-vision@1.0.1`
- WASM 與 JS 使用相同版本
- JavaScript / WASM / 模型都有載入逾時處理
- 失敗時右上角會顯示實際錯誤，而不是無限「載入中」
- 載入失敗時可直接點右上角狀態重新嘗試

部署 GitHub Pages 後，建議按 Ctrl+F5 強制重新整理，避免瀏覽器沿用舊的 app.js 快取。

## V14.2 一鍵標準化頭頂留白修正

V14 / V14.1 雖設定頭頂留白約 5.5%，但仍可能產生 20%～30% 白邊。

原因是會員照裁切框使用固定 21:23 比例時，若理想裁切框超過原圖寬度或底部空間，
舊版會呼叫 `mpClampRect()` 縮小 `w / h`，但原先依較大裁切框計算的 `y`
沒有重新依新高度計算，因此有效頭頂留白比例被放大。

V14.2 改為：

1. 先計算理想裁切高度（頭頂到下顎約占 75%）
2. 再依三項限制決定「最終裁切高度」：
   - 來源照片寬度
   - 來源照片底部剩餘空間
   - 來源照片上方空間
3. 以最終高度重新計算 `y = headTop - 5.5% × cropH`
4. 不再讓 `mpClampRect()` 在最後階段縮小會員照裁切框
5. 如果下方空間不足，優先讓裁切框變矮、頭部稍微變大，而不是把整個框往上移

因此頭頂留白會真正維持接近 5%～6%。
標準化完成訊息也會顯示實際偵測到的「頭頂留白約 X%」，方便測試。


## V14.2.1 智慧防重疊候選框

針對掃描表已能抓到所有人臉，但候選框過大、互相重疊的情況，新增四層保護：

### 1. 鄰近人臉中線限制
同一列的相鄰人臉，左右邊界不超過兩張臉中心的中點。
同一欄的上下人臉，上下邊界也採相同方式。

### 2. 候選框不得包含其他人臉中心
產生候選框後再檢查一次。
如果框內仍包含另一張臉的中心點，會沿兩張臉中線再次縮框。

### 3. 表格線輔助
掃描頁會建立全頁垂直 / 水平長線分數。
只在格線明顯且位於目標人臉外側時，才用來輔助限制候選框。
格線不是主要偵測依據，因此照片貼歪、超出格子時仍以人臉為主。

### 4. 拆分後多臉檢查
每張候選照片真正拆出後，再跑一次 MediaPipe：

- 1 張臉：正常
- 2 張以上：依原候選目標臉位置自動再縮框
- 自動縮框後只剩 1 張：繼續處理
- 0 張臉或仍有多臉：標記「需人工」，不進一鍵標準化

批次清單會保留拆圖檢查訊息，方便知道哪張曾經自動縮框或需要人工確認。

## V14.5.1.1 標準化流程順序與模式介面

### 一鍵標準化 / 批次 Preset
需要去背的流程改為：

`去背 / 背景判斷 → 自動轉正 → 會員照裁切 → 智慧提亮 → 臉部去污 → 品質檢查`

原因：
先將人物與背景分離後，再進行頭頂、頭髮與會員照裁切分析，可降低背景干擾。

- `會員卡標準｜白底`：第一步先判斷背景；非純白則先去背轉白。
- `會員卡標準｜透明背景`：第一步直接透明去背。
- `會員卡標準｜保留背景`：不去背，從自動轉正開始。
- `只做會員照裁切`：只執行裁切。

透明背景流程在自動轉正時會保留 Alpha，不會因旋轉補成白色背景。

### 批次裁切按鈕
`🎯 自動會員照` 改名為：
`🎯 自動化會員照裁切`

功能本身仍是「只對批次照片執行會員照自動裁切」，不是完整 Preset。

### 左側照片欄
- 單張修圖：只顯示「照片資訊」
- 批次處理：才顯示「批次照片 / Preset / 狀態篩選 / 名稱清單」
- 掃描表拆圖：使用獨立掃描頁介面

並新增 CSS 強制隔離，避免 `.batch-panel { display:flex }` 等樣式在部分瀏覽器讓 hidden 元素意外顯示。

## V14.5.1 掃描頁放大後頂端被遮住修正

V14.5 的 `.scan-stage` 使用 Flex：
- `align-items:center`
- `justify-content:center`

當 canvas 放大到比捲動容器更高時，Flex 的垂直置中會讓 canvas 上半部產生負方向位移，
因此 `scrollTop = 0` 也無法到達圖片真正最上方。

V14.5.1 改為：
- `.scan-stage` 使用一般 block 捲動容器
- `.scan-canvas-wrap` 使用 `width:max-content`
- 小於工作區：JS 計算正的 `margin-top` 保持置中
- 大於工作區：`margin-top = 0`
- 水平由 `margin-left/right:auto` 處理，小圖置中、大圖自動從可捲動左側開始

縮放本身仍只影響預覽，不改變拆圖解析度。
